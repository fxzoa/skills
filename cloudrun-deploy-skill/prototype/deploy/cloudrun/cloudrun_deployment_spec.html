GCP Cloud Run Architecture Spec Plan B (All-in-One)

coin-trade-kaggle: Cloud Run 統合デプロイ仕様書

単一コンテナ内で統合ダッシュボード・WebUI群・常駐取引ボットを安全に稼働させる構成と実行手順

1. アーキテクチャ全体像

Cloud Run の CPU常時割り当て（--no-cpu-throttling） を活用し、8080番ポートのダッシュボードをゲートウェイとして公開。内部バックグラウンドプロセスとして各種ボット・ワーカーおよび各機能WebUIを統括起動します。

3. デプロイ手順（クイックスタート）

前提条件

Google Cloud SDK (gcloud) がインストールされ、対象GCPプロジェクトの権限（Cloud Run管理者、Artifact Registry管理者）で認証済みであること。

ステップ 1: 環境変数の設定

export GCP_PROJECT_ID="your-gcp-project-id"
export GCP_REGION="asia-northeast1"
export CLOUDRUN_SERVICE_NAME="coin-trade-all-in-one"

ステップ 2: デプロイスクリプトの実行

cd /mnt/d/coin-trade-kaggle
./deploy/cloudrun/deploy.sh

ステップ 3: （オプション）Secret Manager を用いた秘密鍵の登録

外部RedisへのSSHトンネルが必要な場合、秘密鍵を Secret Manager に登録して環境変数 SSH_PRIVATE_KEY またはマウントとして注入します：

gcloud secrets create redis-ssh-key --data-file=conf/redis_tunnel/id_key
gcloud run services update coin-trade-all-in-one \
  --set-secrets="SSH_PRIVATE_KEY=redis-ssh-key:latest" \
  --set-env-vars="ENABLE_REDIS_TUNNEL=true,SSH_TARGET=user@your-vps-ip"

4. 運用・検証ポイント

  • ヘルスチェック: Cloud Run は /api/health (Port 8080) を定期監視します。
  • CPU常時割り当て: ボットがスリープせずに取引シグナルを監視し続けるため、--no-cpu-throttling を必ず指定します。
  • 単一インスタンス制限: 取引ボットの二重発注を防ぐため、--max-instances=1 を指定しています。
